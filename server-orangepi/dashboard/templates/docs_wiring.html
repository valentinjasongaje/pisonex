🔌 Hardware Wiring Guide

This build uses the coin slot only — the keypad and LCD have been removed. Coin acceptance is triggered from each PC's Insert Coin button on the client lock screen. The GPIO pins below can be changed any time from Settings → Coin Slot Hardware without editing files.

Components Used

UCB Mini v4 Coin Acceptor — detects ₱1, ₱5, ₱10

Relay Module — cuts coin acceptor power when idle

GPIO Numbering

All GPIO numbers in this guide use OPi.GPIO BCM mode (Allwinner SoC port numbering: PA0=0, PB0=32, PC0=64, etc.).

To list available pins, run: gpio readall on your Orange Pi terminal.

The coin and relay pins are editable from Settings → Coin Slot Hardware.

Component

Model: UCB Mini v4 coin acceptor

Input Voltage: 12V DC

Signal Output: 5V pulse (one pulse per peso)

Accepted: ₱1 (1 pulse), ₱5 (5 pulses), ₱10 (10 pulses)

Signal Timing

Debounce: 30 ms (ignores bounces shorter than this)

Pulse gap: ~50–80 ms between pulses (UCB Mini v4)

Finalize timeout: 3.0 s of silence → total is calculated

Default polarity: FALLING edge (optocoupler inverts signal)

⚠️ CRITICAL: The UCB Mini v4 outputs a 5V signal. The Orange Pi GPIO is 3.3V tolerant only. You MUST use a voltage divider before connecting to GPIO — direct connection will permanently damage the GPIO pin.
Voltage Divider Circuit (5V → 3.3V)
UCB Mini v4 Orange Pi SIG (5V) ──────── 1kΩ ──────┬──────── GPIO 4 (Pin 7) │ 2kΩ Vout = 5 × 2/(1+2) = 3.33V ✓ │ GND
Use 1kΩ and 2kΩ resistors. Any equivalent ratio (e.g. 2kΩ + 4kΩ) works as long as the output stays ≤ 3.3V.

Signal Polarity

FALLING (default)

Signal rests HIGH, goes LOW on each coin pulse.

Typical for boards with an optocoupler that inverts the signal.

Set in Settings → Coin Slot Hardware: Signal Edge = FALLING.

RISING

Signal rests LOW, goes HIGH on each coin pulse.

Typical for direct/buffer connections without signal inversion.

Set in Settings → Coin Slot Hardware: Signal Edge = RISING.

Run sudo venv/bin/python test_coin_signal.py to auto-detect which polarity your board uses before configuring.

Purpose

The relay cuts power to the coin acceptor when no PC is accepting coins. This prevents coins from registering when no session is pending, and stops the coin acceptor drawing 12V power unnecessarily.

Behavior

GPIO 6 HIGH → Relay ON → Coin acceptor powered → accepts coins

GPIO 6 LOW  → Relay OFF → Coin acceptor unpowered → rejects coins

Relay activates only while the slot is accepting coins for a PC, and deactivates on idle timeout.

Coin Slot Troubleshooting

▶
SymptomLikely CauseFix
No coin detected at all Wrong signal polarity Run test_coin_signal.py, set Signal Edge to RISING or FALLING accordingly in Settings → Coin Slot Hardware.
Coin detected but wrong count (e.g. ₱5 shows as ₱1) Debounce too aggressive — swallowing pulses Lower the Debounce value (try 20ms) in Settings → Coin Slot Hardware.
One coin counted multiple times Debounce too loose — counting noise Raise the Debounce value (try 40ms) in Settings → Coin Slot Hardware.
GPIO overvoltage warning or pin damaged 5V signal connected directly to GPIO Add voltage divider (1kΩ + 2kΩ). GPIO max is 3.3V.
Coin accepted when no PC is selected Relay not cutting power Check relay wiring and the Relay Pin signal with a multimeter.
Coin acceptor never powers on Relay wired to NC instead of NO Move the 12V wire from NC contact to NO contact on the relay.
Insert Coin button does nothing No coin hardware detected, or coin slot disabled for that PC Check the server logs for "Hardware controller started", verify the PC is online, and that the coin slot is enabled for it.
